1. Project Overview

1.1 Description

The Military Asset Management System (MAMS) is a full-stack web application designed to digitize, track, and manage military equipment and assets across multiple bases. The platform provides a centralized dashboard for senior officers and base commanders to monitor the real-time status of inventory, equipment purchases, personnel assignments, inter-base transfers, and expenditure logs.

The system replaces traditional paper-based logistics tracking with a secure, role-restricted digital platform — ensuring that all equipment movements are recorded, traceable, and auditable through a comprehensive audit logging mechanism.

1.2 Key Features

  • Real-time Inventory tracking across multiple military bases
  • Equipment Purchases management with quantity and cost tracking
  • Inter-Base Transfer management with source/destination validation
  • Personnel Assignment tracking with status (Active / Returned)
  • Expenditure logging for damaged, lost, or consumed assets
  • Dashboard with live charts, metrics, and advanced filters (Date, Base, Equipment Type)
  • Audit Log for all system-level API transactions (POST, PUT, DELETE)
  • User and Base Management via Admin-only Settings panel
  • JWT-based Authentication with Role-Based Access Control (RBAC)
  • Dark/Light theme toggle with persistent user preference

1.3 Assumptions

  • Each military base is a distinct entity with its own dedicated inventory pool.
  • Each user account is assigned to exactly one base at the time of creation.
  • All financial values are expressed in Indian Rupees (INR / ₹).
  • The system is intended to run on a closed intranet and not exposed to the public internet.
  • Equipment types are pre-defined by the Administrator and are shared globally across all bases.
  • All dates and times are recorded in UTC and displayed in the user's local timezone.

1.4 Limitations

  • No file upload support for purchase orders or transfer documents.
  • Email notification functionality is configured in settings but not connected to a mail server.
  • No real-time push notifications; users must refresh pages to see updated data.
  • Application is English-only; no multi-language (i18n) support.
  • Report exports (PDF/Excel per module) are not yet implemented.
  • Mobile responsiveness is partially implemented; optimized for desktop use.

2. Tech Stack & Architecture

2.1 Backend — Spring Boot 3 (Java 17)

The backend is a RESTful API server built with Spring Boot 3, leveraging the Spring ecosystem for rapid development. Spring Security handles JWT authentication, while Spring Data JPA and Hibernate manage all database operations via ORM.

2.2 Frontend — React 18 (Vite)

The frontend is a Single Page Application (SPA) built with React 18 and bootstrapped with Vite for fast development. UI uses Bootstrap 5 and React-Bootstrap for consistent, responsive layout.

2.3 Database — MySQL 8

MySQL 8 is the relational database. Hibernate auto-generates and updates the schema using ddl-auto=update based on JPA entity annotations. The database runs on port 3308 to avoid conflict with any default MySQL installation.

4.3 Backend Enforcement

Each REST controller extracts the authenticated principal via Spring Security's SecurityContextHolder, fetches the User entity from the database, and checks the role field before processing any request. Unauthorized requests receive HTTP 403 Forbidden.

// AssetController.java — Role-Based Inventory Filter Authentication auth = SecurityContextHolder.getContext().getAuthentication(); User user = userRepository.findByUsername(auth.getName()).orElse(null); if (user.getRole().contains("ADMIN")) { return assetRepository.findAll(); // All bases } else { return assetRepository.findByBaseId(user.getBase().getId()); // Own base only }

4.4 Frontend Enforcement

Sidebar navigation links are conditionally rendered in Layout.jsx based on the role stored in the JWT payload in localStorage. Protected action buttons (e.g., "Add Purchase") are hidden for unauthorized roles. This is a UX-layer guard only — all real security is enforced by the backend API.

5. API Logging

5.1 Mechanism Overview

All write-operations (POST, PUT, DELETE) are automatically captured by a Spring MVC HandlerInterceptor called AuditInterceptor. This interceptor fires after every HTTP response is committed (afterCompletion phase), ensuring that both successful and failed requests are logged to the audit_logs table.

5.2 Fields Captured

FieldDescription
timestampUTC datetime of the API call
http_methodPOST / PUT / DELETE
api_endpointFull URL path (e.g., /api/purchases)
entity_typeModule name extracted from the URL segment
statusSUCCESS (2xx response) or FAILED (non-2xx)
user_idID of the authenticated user; NULL for system actions
actionCombined HTTP method and path string
descriptionHuman-readable description of the performed action

5.3 AuditInterceptor Code

// AuditInterceptor.java @Override public void afterCompletion(HttpServletRequest req, HttpServletResponse res, ...) { String method = req.getMethod(); if (method.equals("POST") || method.equals("PUT") || method.equals("DELETE")) { String path = req.getRequestURI(); String status = (res.getStatus() >= 200 && res.getStatus() < 300) ? "SUCCESS" : "FAILED"; String entity = path.split("/").length > 2 ? path.split("/")[2] : "UNKNOWN"; auditService.log(method + " " + path, entity, null, "User performed " + method + " " + path, method, path, status); } }

5.4 Viewing Logs

Access: Only ROLE_ADMIN users can view audit logs.
Location in App: Sidebar → Audit Logs
Display: Sorted newest-first. HTTP method and status have colored badge indicators.

6. Setup Instructions

6.1 Prerequisites

  • Java 17 or later (JDK installed and JAVA_HOME set)
  • Node.js 18+ with npm
  • MySQL 8 running on port 3308
  • Git installed (for cloning the repository)

6.2 Database Setup

-- Connect to MySQL (port 3308) mysql -u root -p --port=3308 -- Create the database CREATE DATABASE military_asset_management; -- The schema will be auto-created by Hibernate on first startup. -- Optionally, import the SQL file for pre-seeded data: USE military_asset_management; SOURCE /path/to/database/military_asset_management.sql;

6.3 Backend Setup & Run

# Navigate to backend folder cd military-asset-management/backend # Run using Maven wrapper (Linux / Mac) ./mvnw spring-boot:run # Run using Maven wrapper (Windows CMD) mvnw.cmd spring-boot:run

The backend starts at http://localhost:8080. On first startup, DataLoader auto-creates the admin user and Central Base if they don't already exist.

Key application.properties settings:
DB URL: jdbc:mysql://localhost:3308/military_asset_management
DB Username: root  |  DB Password: root
JWT Expiry: 86400000 ms (24 hours)

6.4 Frontend Setup & Run

# Navigate to frontend folder cd military-asset-management/frontend # Install all npm dependencies npm install # Start Vite development server npm run dev

The frontend is accessible at http://localhost:5173. Open this URL in a web browser to use the application.
