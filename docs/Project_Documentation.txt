1. PROJECT OVERVIEW
================================================================================

1.1 Description
----------------
The Military Asset Management System (MAMS) is a full-stack web application
designed to digitize, track, and manage military equipment and assets across
multiple bases. The platform provides a centralized dashboard for senior
officers and base commanders to monitor the real-time status of inventory,
equipment purchases, personnel assignments, inter-base transfers, and
expenditure logs.

The system replaces traditional paper-based logistics tracking with a secure,
role-restricted digital platform ensuring all equipment movements are recorded,
traceable, and auditable through a comprehensive audit logging mechanism.


1.2 Key Features
-----------------
- Real-time Inventory tracking across multiple military bases
- Equipment Purchases management with quantity and cost tracking
- Inter-Base Transfer management with source/destination validation
- Personnel Assignment tracking with status (Active / Returned)
- Expenditure logging for damaged, lost, or consumed assets
- Dashboard with live charts, metrics, and advanced filters
  (Date Range, Base, Equipment Type)
- Audit Log for all system-level API transactions (POST, PUT, DELETE)
- User and Base Management via Admin-only Settings panel
- JWT-based Authentication with Role-Based Access Control (RBAC)
- Dark/Light theme toggle with persistent user preference


1.3 Assumptions
----------------
- Each military base is a distinct entity with its own dedicated inventory pool.
- Each user account is assigned to exactly one base at account creation time.
- All financial values are expressed in Indian Rupees (INR / Rs.).
- The system operates on a closed intranet and is not exposed to the public.
- Equipment types are pre-defined by the Administrator and shared globally
  across all bases.
- All dates and times are recorded in UTC and displayed in local timezone.


1.4 Limitations
----------------
- No file upload support for purchase orders or transfer documents.
- Email notifications are configurable in settings but not connected to a
  mail server in this version.
- No real-time push notifications; users must refresh to see updated data.
- Application is English-only; no multi-language (i18n) support.
- Report exports (PDF/Excel per module) are not yet implemented.
- Mobile responsiveness is partially implemented; optimized for desktop use.

2. TECH STACK & ARCHITECTURE
================================================================================

2.1 Backend - Spring Boot 3 (Java 17)
---------------------------------------
Framework   : Spring Boot 3.x
ORM         : Spring Data JPA / Hibernate
Security    : Spring Security + JWT (JSON Web Tokens)
API Docs    : SpringDoc (Swagger UI / OpenAPI)
Build Tool  : Apache Maven
Language    : Java 17 (LTS)

Why chosen:
- Spring Boot provides production-ready REST APIs with minimal configuration.
- Spring Security offers robust authentication and authorization mechanisms.
- Hibernate simplifies database interaction with ORM and auto schema generation.
- Java 17 is a long-term support version with modern language features.


2.2 Frontend - React 18 (Vite)
--------------------------------
Framework   : React 18
Build Tool  : Vite (fast HMR, modern ES module builds)
UI Library  : Bootstrap 5 + React-Bootstrap
Routing     : React Router v6
HTTP Client : Axios (Promise-based with JWT interceptors)
Charts      : Recharts (SVG-based responsive charts)
Icons       : Bootstrap Icons

Why chosen:
- React enables component-based, reusable UI development.
- Vite provides significantly faster hot module replacement than CRA.
- Bootstrap 5 delivers consistent, responsive layouts quickly.
- Recharts integrates easily with React for live data visualizations.


2.3 Database - MySQL 8
-----------------------
- Relational database running on port 3308 (custom, to avoid port conflicts).
- Hibernate auto-generates and updates schema using ddl-auto=update.
- Stores all entities: bases, users, assets, purchases, transfers,
  assignments, expenditures, audit_logs, equipment_types.

Why chosen:
- Mature, reliable RDBMS with strong support for relational data models.
- Excellent compatibility with Spring Data JPA / Hibernate.
- ACID compliance ensures data integrity across all transactions.


2.4 Architecture Overview
--------------------------

  Browser (React SPA - port 5173)
         |
         |  HTTP/REST  (Axios + JWT Bearer Token)
         |
         v
  Spring Boot API Server (port 8080)
    |-- SecurityConfig       JWT filter chain, role enforcement
    |-- AuditInterceptor     Logs every POST, PUT, DELETE request
    |-- Controllers          Route handlers per feature module
    |-- Repositories         JPA queries to MySQL
         |
         v
  MySQL Database (port 3308)
    -- Schema: military_asset_management

-------------------|---------------------------|-----------------------------

4.2 Permission Matrix
----------------------
Feature / Module             | Admin | Commander | Logistics
-----------------------------|-------|-----------|----------
Dashboard (global view)      | YES   | Base only | Base only
Inventory (all bases)        | YES   | Base only | Base only
Create Purchase              | YES   | NO        | YES
Initiate Transfer            | YES   | YES*      | YES*
Assignments (Create/View)    | YES   | YES*      | NO
Expenditures (Create/View)   | YES   | YES*      | NO
Audit Logs                   | YES   | NO        | NO
User Management              | YES   | NO        | NO
Settings (Bases/Equip Types) | YES   | NO        | NO

* Restricted to own base only


4.3 Backend Enforcement
------------------------
Each REST controller extracts the authenticated user from Spring Security's
SecurityContextHolder, fetches the User entity from the database, and checks
the 'role' field before processing any request. If unauthorized, the API
returns HTTP 403 Forbidden.

Example from AssetController.java:

    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    User user = userRepository.findByUsername(auth.getName()).orElse(null);

    if (user.getRole().contains("ADMIN")) {
        return assetRepository.findAll();             // All bases
    } else {
        return assetRepository.findByBaseId(         // Own base only
                   user.getBase().getId());
    }


4.4 Frontend Enforcement
-------------------------
Sidebar navigation links are conditionally rendered in Layout.jsx based on
the role stored in the JWT payload (localStorage). Protected action buttons
such as "Add Purchase" are hidden for unauthorized roles. This is a UX-layer
guard only. All real security is enforced strictly by the backend API.

JWT Token:
- Issued on successful login with a 24-hour expiry.
- Stored in localStorage.
- Attached as a Bearer token on every API request.

5. API LOGGING
================================================================================

5.1 Mechanism Overview
-----------------------
All write operations (POST, PUT, DELETE) are automatically captured by a
Spring MVC HandlerInterceptor called AuditInterceptor. This interceptor fires
after every HTTP response is committed (afterCompletion phase), ensuring both
successful and failed requests are recorded in the audit_logs table.


5.2 Fields Captured Per Log Entry
-----------------------------------
Field           | Description
----------------|-------------------------------------------------------
timestamp       | UTC datetime of the API call
http_method     | POST / PUT / DELETE
api_endpoint    | Full URL path (e.g. /api/purchases)
entity_type     | Module name extracted from URL (e.g. purchases)
status          | SUCCESS (HTTP 2xx) or FAILED (non-2xx)
user_id         | Authenticated user ID; NULL for system-level actions
action          | Combined HTTP method and path string
description     | Human-readable description of the performed action


5.3 AuditInterceptor Code (Simplified)
----------------------------------------

    @Override
    public void afterCompletion(HttpServletRequest req,
                                HttpServletResponse res, ...) {
        String method = req.getMethod();
        if (method.equals("POST") || method.equals("PUT")
                                  || method.equals("DELETE")) {
            String path   = req.getRequestURI();
            String status = (res.getStatus() >= 200 && res.getStatus() < 300)
                            ? "SUCCESS" : "FAILED";
            String entity = path.split("/").length > 2
                            ? path.split("/")[2] : "UNKNOWN";
            auditService.log(method + " " + path, entity, null,
                     "User performed " + method + " " + path,
                     method, path, status);
        }
    }


5.4 AuditService
-----------------
AuditService resolves the currently authenticated user from SecurityContext,
creates an AuditLog entity, and persists it to the audit_logs table via
AuditLogRepository. If no authenticated user exists (e.g. login endpoint),
user_id is stored as NULL and displayed as "System" in the UI.


5.5 Viewing Audit Logs
-----------------------
- Access    : ROLE_ADMIN only
- Location  : Sidebar -> Audit Logs
- Display   : Sorted newest-first. HTTP method and status shown with
              color-coded badges (POST=blue, DELETE=grey,
              SUCCESS=green, FAILED=red)

6. SETUP INSTRUCTIONS
================================================================================

6.1 Prerequisites
------------------
- Java 17 or later (JDK installed, JAVA_HOME set in environment variables)
- Node.js 18+ with npm
- MySQL 8 running on port 3308
- Git installed

6.2 Database Setup
-------------------
Step 1: Connect to MySQL

    mysql -u root -p --port=3308

Step 2: Create the database

    CREATE DATABASE military_asset_management;

Step 3: (Optional) Import initial SQL schema

    USE military_asset_management;
    SOURCE /path/to/database/military_asset_management.sql;

Note: The backend uses spring.jpa.hibernate.ddl-auto=update, so all tables
are auto-created by Hibernate on first startup. The SQL file is only needed
for pre-seeded demo data.


6.3 Backend Setup & Run
------------------------
Step 1: Navigate to backend folder

    cd military-asset-management/backend

Step 2: Run using Maven wrapper

    On Linux / Mac:
    ./mvnw spring-boot:run

    On Windows CMD:
    mvnw.cmd spring-boot:run

The backend starts at: http://localhost:8080

On first startup, DataLoader automatically:
- Creates the default admin user account
- Creates the "Central Base" if none exists


Key application.properties settings:
    DB URL      : jdbc:mysql://localhost:3308/military_asset_management
    DB Username : root
    DB Password : root
    JWT Expiry  : 86400000 ms (24 hours)


6.4 Frontend Setup & Run
-------------------------
Step 1: Navigate to frontend folder

    cd military-asset-management/frontend

Step 2: Install all dependencies

    npm install

Step 3: Start Vite development server

    npm run dev

The frontend is accessible at: http://localhost:5173


6.5 Git Commands to Push to GitHub (Windows CMD)
-------------------------------------------------
Run these commands in Windows CMD (not PowerShell):

    :: Navigate to project folder
    cd "d:\new project\military-asset-management"

    git remote set-url origin https://srushtisd24:YOUR_PAT_TOKEN@github.com/srushtisd24/Milatary_Assest_Management_System.git
